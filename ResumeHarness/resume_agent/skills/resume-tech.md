# 互联网/科技行业简历专项技能

## 行业概述

互联网/科技行业简历强调技术深度、业务影响力和工程化能力。招聘方通常使用 ATS 系统进行关键词筛选，简历需要同时满足机器筛选和人工审查的要求。

## 核心关键词分类

### 后端开发关键词

- **编程语言**：Java、Go、Python、C++、Rust、Node.js
- **框架/中间件**：Spring Boot、Spring Cloud、gRPC、Dubbo、Kafka、RabbitMQ、Redis、Elasticsearch
- **数据库**：MySQL、PostgreSQL、MongoDB、ClickHouse、TiDB
- **基础设施**：Kubernetes、Docker、Prometheus、Grafana、Nginx、Envoy
- **架构**：微服务、分布式系统、高可用、高并发、服务网格、DDD

### 前端开发关键词

- **框架**：React、Vue 3、Next.js、Nuxt.js、Svelte
- **工程化**：Webpack、Vite、Rollup、Babel、ESLint、CI/CD
- **语言**：TypeScript、JavaScript、CSS、HTML5
- **跨端**：React Native、Flutter、Electron、小程序
- **性能**：SSR、SSG、懒加载、PWA、Web Vitals

### 算法/AI 关键词

- **机器学习**：PyTorch、TensorFlow、Scikit-learn、XGBoost
- **NLP/CV**：Transformer、BERT、GPT、LLM、RAG、Diffusion Model
- **数据**：Spark、Flink、Hadoop、Hive、Pandas、SQL
- **部署**：ONNX、TensorRT、vLLM、Triton、Model Serving

### 产品/运营关键词

- **产品**：需求分析、PRD、用户研究、A/B 测试、数据驱动、竞品分析
- **运营**：用户增长、留存率、DAU/MAU、转化漏斗、ROI、拉新促活
- **分析**：SQL、Python、Tableau、Excel、数据埋点、指标体系

## 简历优化要点

### 1. 量化成果是核心竞争力

科技行业简历必须大量使用量化数据，缺少数据的简历几乎无法通过筛选。

**量化维度参考**：
- **性能提升**：响应时间、QPS、吞吐量、延迟降低百分比
- **业务影响**：收入增长、用户增长、转化率提升、成本节约
- **规模指标**：DAU/MAU、数据量、请求量、团队规模
- **效率提升**：开发效率、上线频率、构建时间、部署时间

**示例**：
```
- **性能优化**：主导商品详情页性能重构，LCP 从 4.2s 降至 1.1s，转化率提升 18%，日均 PV 500 万+
- **架构升级**：设计微服务拆分方案，将单体应用拆分为 12 个服务，部署频率从月发提升至周发，故障恢复时间从 2h 降至 15min
- **成本优化**：通过弹性扩缩容 + 资源利用率优化，服务器成本降低 40%，同时支撑双 11 峰值 QPS 10 万+
```

### 2. 技术栈要与 JD 精确匹配

- JD 中提到的每个技术关键词，如果简历中有相关经验，**必须**在简历中体现
- 使用 JD 中的原始术语，不要自行替换（如 JD 写"K8s"，简历不要写"Kubernetes"）
- 技能标签的排列顺序按 JD 匹配度排序，最相关的放最前

### 3. 突出技术决策和架构能力

对于中高级岗位，技术决策能力比编码能力更重要：

```
- **技术选型**：对比评估 3 种消息队列方案，最终选择 Kafka，支撑日均 10 亿消息吞吐
- **架构设计**：设计多租户 SaaS 架构，支持 500+ 企业客户隔离部署，资源利用率提升 60%
- **技术治理**：建立前端微服务治理体系，制定技术雷达和架构评审机制
```

### 4. 适当展示开源和技术影响力

- GitHub 贡献、开源项目维护
- 技术博客、社区分享、技术演讲
- 专利、论文、技术标准参与

**示例**：
```
- **开源贡献**：Vue 3 核心贡献者，累计 PR 50+，维护 XX 组件库（GitHub 2k+ Star）
- **技术分享**：公司内部分享 20+ 次，QCon/GMTC 演讲嘉宾 3 次
```

## 常见 JD 解读

### "熟悉/掌握/精通"的对应策略

| JD 用词 | 简历策略 |
|---------|---------|
| 精通 XX | 列举 XX 的深度使用经验，包括原理、优化、踩坑 |
| 熟悉 XX | 展示 XX 的实际项目使用经验，说明使用场景 |
| 了解 XX | 如有经验则简要提及，如无则不写（不要虚写） |
| 有 XX 经验优先 | 如有相关经验，在个人简介和工作经历中重点突出 |

### 常见隐性要求解读

| JD 表述 | 实际含义 | 简历应对 |
|---------|---------|---------|
| "能承受工作压力" | 可能有加班 | 无需特别回应，面试时了解 |
| "有从 0 到 1 经验" | 创业/新业务经验 | 突出项目从零搭建的经历 |
| "跨团队协作能力" | 需要与多方沟通 | 突出跨部门项目协作经验 |
| "自驱力强" | 需要主动推动事情 | 突出主动发现和解决问题的案例 |
| "技术热情" | 关注技术发展 | 展示技术博客、开源、学习经历 |

## 不同职位层级策略

### 初级工程师（1-3 年）

- 重点突出技术广度和学习能力
- 展示完整的项目参与经历
- 突出解决问题的能力和成长速度
- 开源贡献和业余项目可以作为加分项

### 中级工程师（3-5 年）

- 重点突出技术深度和独立负责能力
- 展示技术选型和方案设计经验
- 量化项目成果和业务影响
- 适当展示技术影响力

### 高级工程师/架构师（5+ 年）

- 重点突出架构设计和技术决策能力
- 展示跨团队协作和技术推动能力
- 强调业务理解和产品思维
- 量化技术对业务的实际影响
- 团队培养和技术文化构建

### 技术管理岗

- 重点突出团队管理和组织能力
- 展示团队建设成果（招聘、培养、文化）
- 强调技术战略规划能力
- 量化团队产出和业务成果
- 跨部门协作和向上管理能力
