# 简历优化领域技能

## 核心原则

1. **ATS 友好**：简历需要通过 Applicant Tracking System（ATS）的自动筛选，关键词匹配至关重要
2. **STAR 法则**：描述工作经历时使用 Situation-Task-Action-Result 结构
3. **量化成果**：尽可能用数据量化工作成果（提升百分比、处理量、团队规模等）
4. **匹配岗位**：根据 JD 调整关键词和突出重点，而非千篇一律

## 简历结构优化

### 标准简历模块（严格按此顺序）

1. **个人信息**：姓名（一级标题）、联系方式（姓名下方一行，`|` 分隔）
2. **个人简介**：1-2 句话概括核心优势和求职意向
3. **工作经历**：按时间倒序，每段经历 3-5 个要点
4. **教育背景**：学历、学校、专业
5. **专业技能**：与目标岗位匹配的技术栈和软技能
6. **项目经历**：选取最能体现匹配度的项目

### 排版要点

- 简历控制在 1-2 页（经验丰富者 2 页，初级 1 页）
- 使用清晰的层级结构（一/二/三级标题）
- 关键词自然融入上下文，避免堆砌
- 统一使用 Markdown 格式

## 关键词匹配策略

### 提取 JD 关键词

1. **硬技能关键词**：编程语言、框架、工具、平台
2. **软技能关键词**：团队协作、跨部门沟通、项目管理
3. **行业术语**：特定领域的专业术语
4. **量化指标关键词**：KPI、ROI、转化率等

### 匹配原则

- JD 中出现的技能，如用户简历中有，**必须**在简历中突出
- JD 中的高级要求，如用户部分满足，用"熟悉/了解"等词诚实表达
- 避免 JD 中完全没有关联的无关技能堆砌
- 同一技能使用 JD 中的原始表述（如 JD 写"React"，简历不要写"React.js"）

## 工作经历优化

### STAR 法则示例

```
Situation: 公司客服系统响应慢，客户投诉率高
Task: 负责系统性能优化
Action: 引入 Redis 缓存 + 异步队列，重构核心查询逻辑
Result: 响应时间从 3s 降至 200ms，客户满意度提升 30%
```

### 转化为简历要点

```
- **系统性能优化**：主导客服系统重构，引入 Redis 缓存与异步队列，将响应时间从 3s 降至 200ms，客户满意度提升 30%
```

### 要点优化技巧

- 每个要点以动词开头（主导/负责/设计/开发/优化/推动/搭建/实现/带领）
- 量化指标优先（数字比形容词更有说服力）
- 突出业务影响而非仅技术实现
- 每个要点控制在 30-50 字
- 避免使用"参与了""协助了"等弱动词，改用"负责""主导""推动"

### 工作经历格式要求

每段工作经历必须包含：
- **职位名称** - **公司名称**（**时间段**）
- 3-5 个要点，每个要点以粗体关键词开头

**正确示例**：
```
### 高级前端工程师 - XX科技有限公司（2021.06 - 至今）

- **性能优化**：主导电商平台首页性能优化，通过 SSR + 懒加载方案将 LCP 从 4.2s 降至 1.1s，转化率提升 18%
- **架构升级**：设计并落地微前端架构，将 5 个独立子系统整合为统一平台，开发效率提升 40%
- **团队建设**：带领 6 人前端团队，建立代码规范和 CR 机制，代码缺陷率降低 35%
```

**错误示例**（避免）：
```
### XX科技有限公司

负责前端开发工作，参与了多个项目的开发。使用 React 和 Vue 进行开发，熟悉各种前端技术。
```
> 错误原因：缺少职位、时间段；要点过于笼统、没有量化、没有粗体关键词

## 不同场景策略

### 应届生简历

- 重点突出教育背景、实习经历、项目经验
- 展示学习能力和成长潜力
- GPA/奖项/竞赛经历适当展示
- 个人简介强调求职方向和学习热情
- 工作经历不足时，项目经历和技能标签权重提升

### 转行简历

- 突出可迁移技能（沟通、分析、项目管理）
- 用项目经历补充行业经验不足
- 个人简介明确转型动机和优势
- 技能标签突出新行业所需技能
- 工作经历重新组织，强调与新行业相关的成果

### 高级职位简历

- 突出战略思维和业务影响
- 强调团队管理和跨部门协作
- 展示技术决策和架构设计能力
- 量化团队规模、业务指标、技术影响力
- 个人简介强调领导力和行业影响力

## 联系方式格式

联系方式必须放在姓名下方的**同一行**，用 `|` 分隔，格式如下：

```
# 张三
zhangsan@email.com | 138-0000-1234 | 北京
```

可选字段按需添加：`| 个人网站 | LinkedIn | 微信：xxx`

**注意**：不要在姓名下方换行展示联系方式，必须在一行内完成。

## 专业技能格式

技能必须按类别分组，使用粗体类别名 + 冒号 + 技能列表的格式：

```
## 专业技能

- **前端框架**：React、Vue 3、Next.js
- **工程化**：Webpack、Vite、CI/CD、Docker
- **编程语言**：TypeScript、JavaScript、Python
- **软技能**：团队管理、跨部门协作、技术方案评审
```

**注意**：
- 每个类别一行，用顿号（、）分隔技能项
- 技能顺序按与目标岗位的相关度排列，最相关的放最前
- 软技能和硬技能分开归类

## 项目经历格式

每个项目必须包含项目名称、角色、时间段，以及项目描述和核心贡献：

```
## 项目经历

### 电商平台重构 - 核心开发（2022.01 - 2022.12）

- **项目描述**：公司核心电商平台从 jQuery 迁移至 React + 微前端架构，日均 PV 500 万+
- **核心贡献**：设计微前端路由分发方案，实现子应用独立部署，上线效率提升 60%
- **核心贡献**：优化首屏加载策略，FCP 从 3.5s 降至 0.9s，用户跳出率降低 22%
```

## 常见问题

1. **简历太长**：删减与目标岗位无关的经历，控制在 2 页以内；优先保留最近 3-5 年经历
2. **缺乏量化数据**：引导用户提供具体数字，或基于行业经验合理估算（需注明为估算值）
3. **格式混乱**：统一使用 Markdown 格式输出，确保结构清晰
4. **关键词堆砌**：关键词需要自然融入上下文，避免生硬插入
5. **内容重复**：同一成果不要在工作经历和项目经历中重复出现，选择最合适的位置呈现一次
6. **时间断层**：如有较长的职业空窗期，可在个人简介中简要说明

## 输出质量检查清单

生成简历后，逐项检查以下要点：

- [ ] 姓名使用一级标题，且仅出现一次
- [ ] 联系方式在姓名下方同一行，用 `|` 分隔
- [ ] 所有章节使用二级标题，顺序为：个人简介 → 工作经历 → 教育背景 → 专业技能 → 项目经历
- [ ] 每段工作/教育/项目使用三级标题，格式统一
- [ ] 工作经历每个要点以粗体关键词开头
- [ ] 至少 60% 的要点包含量化数据
- [ ] 技能按类别分组，与 JD 关键词匹配
- [ ] 时间格式统一为 `YYYY.MM - YYYY.MM` 或 `YYYY.MM - 至今`
- [ ] 简历正文在 `<!--RESUME-->` 和 `<!--/RESUME-->` 标记之间
- [ ] 非简历内容（优化建议等）放在标记之外
