# 简历优化领域技能

## 核心原则

1. **ATS 友好**：简历需要通过 Applicant Tracking System（ATS）的自动筛选，关键词匹配至关重要
2. **STAR 法则**：描述工作经历时使用 Situation-Task-Action-Result 结构
3. **量化成果**：尽可能用数据量化工作成果（提升百分比、处理量、团队规模等）
4. **匹配岗位**：根据 JD 调整关键词和突出重点，而非千篇一律

## 简历结构优化

### 标准简历模块
- **个人信息**：姓名、联系方式、邮箱（不放照片和年龄，除非用户要求）
- **个人简介**：1-2 句话概括核心优势和求职意向
- **工作经历**：按时间倒序，每段经历 3-5 个要点
- **教育背景**：学历、学校、专业
- **技能标签**：与目标岗位匹配的技术栈和软技能
- **项目经历**：选取最能体现匹配度的项目

### 排版要点
- 简历控制在 1-2 页
- 使用清晰的层级结构
- 关键词自然融入上下文，避免堆砌
- 统一使用 Markdown 格式

## 关键词匹配策略

### 提取 JD 关键词
1. **硬技能关键词**：编程语言、框架、工具、平台
2. **软技能关键词**：团队协作、跨部门沟通、项目管理
3. **行业术语**：特定领域的专业术语
4. **量化指标关键词**：KPI、ROI、转化率等

### 匹配原则
- JD 中出现的技能，如用户简历中有，必须在简历中突出
- JD 中的高级要求，如用户部分满足，用"熟悉/了解"等词诚实表达
- 避免 JD 中完全没有关联的无关技能堆砌

## 工作经历优化

### STAR 法则示例
```
Situation: 公司客服系统响应慢，客户投诉率高
Task: 负责系统性能优化
Action: 引入 Redis 缓存 + 异步队列，重构核心查询逻辑
Result: 响应时间从 3s 降至 200ms，客户满意度提升 30%
```

### 转化为简历要点
- **系统性能优化**：主导客服系统重构，引入 Redis 缓存与异步队列，将响应时间从 3s 降至 200ms，客户满意度提升 30%

### 要点优化技巧
- 每个要点以动词开头（主导/负责/设计/开发/优化/推动）
- 量化指标优先（数字比形容词更有说服力）
- 突出业务影响而非仅技术实现

## 不同场景策略

### 应届生简历
- 重点突出教育背景、实习经历、项目经验
- 展示学习能力和成长潜力
- GPA/奖项/竞赛经历适当展示

### 转行简历
- 突出可迁移技能（沟通、分析、项目管理）
- 用项目经历补充行业经验不足
- 个人简介明确转型动机和优势

### 高级职位简历
- 突出战略思维和业务影响
- 强调团队管理和跨部门协作
- 展示技术决策和架构设计能力

## 常见问题

1. **简历太长**：删减与目标岗位无关的经历，控制在 2 页以内
2. **缺乏量化数据**：引导用户提供具体数字，或基于行业经验合理估算
3. **格式混乱**：统一使用 Markdown 格式输出，确保结构清晰
4. **关键词堆砌**：关键词需要自然融入上下文，避免生硬插入
