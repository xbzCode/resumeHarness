# JD 解析专项技能

## 概述

本技能指导如何从职位描述（JD）中结构化提取关键信息，包括硬技能、软技能、行业术语、隐性要求等，以便精准匹配简历内容。

## JD 解析框架

### 1. 基础信息提取

从 JD 中提取以下基础信息：

| 字段 | 说明 | 示例 |
|------|------|------|
| 岗位名称 | 职位全称 | 高级前端工程师 |
| 所属部门 | 团队/部门名称 | 电商技术部 |
| 工作地点 | 城市/远程 | 北京/上海/远程 |
| 经验要求 | 工作年限 | 3-5 年 / 5 年以上 |
| 学历要求 | 最低学历 | 本科及以上 / 硕士优先 |
| 薪资范围 | 预算区间 | 25k-40k |

### 2. 硬技能提取

从 JD 中提取所有技术/专业技能关键词，按类别分组：

**提取方法**：
- 扫描"任职要求"、"技能要求"、"岗位要求"等章节
- 识别技术名词、工具名、平台名、框架名、协议名
- 注意"熟练/熟悉/了解/精通"等程度词

**分类标准**：

| 类别 | 典型内容 | 识别特征 |
|------|---------|---------|
| 编程语言 | Java、Python、Go、TypeScript | 语言名称 |
| 框架/库 | React、Spring Boot、PyTorch | 框架名+版本号 |
| 工具/平台 | Git、Docker、K8s、Jenkins | 开发运维工具 |
| 数据库 | MySQL、Redis、MongoDB | 数据存储 |
| 方法论 | 敏捷开发、DDD、TDD | 开发方法论 |

### 3. 软技能提取

从 JD 中提取非技术能力要求：

**常见软技能关键词**：

| 类别 | 关键词 |
|------|--------|
| 沟通协作 | 跨部门协作、团队沟通、向上管理、利益相关方管理 |
| 领导力 | 团队管理、项目推动、决策能力、战略思维 |
| 执行力 | 目标导向、结果驱动、自驱力、抗压能力 |
| 创新力 | 创新思维、从 0 到 1、产品思维、商业敏感度 |
| 学习力 | 快速学习、持续成长、技术热情、好奇心 |

### 4. 行业术语提取

识别 JD 中的行业/领域特定术语：

**识别方法**：
- 不属于通用技术的专业名词
- 行业缩写（如 SaaS、B2B、GMV、DAU）
- 业务场景术语（如"交易链路"、"风控策略"、"推荐算法"）
- 合规术语（如"等保三级"、"GDPR"、"数据脱敏"）

### 5. 隐性要求解读

JD 中许多需求不会直接说明，需要从措辞中推断：

| JD 表述 | 隐性要求 | 简历应对策略 |
|---------|---------|-------------|
| "有 XX 经验优先" | 核心加分项 | 如有经验，在工作经历中重点突出 |
| "能独立负责/主导" | 不需要手把手带 | 突出独立完成项目的经历 |
| "有从 0 到 1 经验" | 创业/新业务能力 | 展示项目从零搭建的经历和成果 |
| "跨团队/跨部门" | 沟通协调能力 | 突出跨团队项目经验和协作成果 |
| "抗压/快节奏" | 工作强度大 | 展示在紧张排期下的交付经验 |
| "结果导向/自驱" | 主动性要求 | 突出主动发现问题并解决的案例 |
| "技术热情" | 持续学习 | 展示技术博客、开源、学习经历 |
| "有大厂经验优先" | 工程化/规范化 | 突出规范化流程和大型项目经验 |

### 6. 岗位级别判断

从 JD 措辞判断岗位级别，指导简历深度：

| 信号 | 级别 | 简历重点 |
|------|------|---------|
| "熟悉"、"了解"、"协助" | 初级（1-3 年） | 技术广度、学习能力、项目参与 |
| "熟练"、"独立负责"、"主导" | 中级（3-5 年） | 技术深度、方案设计、项目主导 |
| "精通"、"架构"、"规划" | 高级（5+ 年） | 架构设计、技术决策、业务影响 |
| "带领"、"管理"、"战略" | 管理岗 | 团队建设、业务规划、组织能力 |

## 行业识别策略

根据 JD 内容判断所属行业，用于选择对应的行业技能文件：

### 识别信号

| 行业 | JD 特征信号 |
|------|------------|
| 互联网/科技 | 技术栈关键词密集、敏捷/迭代、用户增长、AB 测试、技术博客 |
| 金融 | 合规/风控/监管关键词、CFA/CPA/FRM、巴塞尔/KYC/AML、交易/清算/风控 |
| 医疗/医药 | 临床/注册/GMP/GCP、医疗器械、药品研发、合规审查 |
| 教育 | 课程设计/教学/教研、学生/学员、K12/职业教育/在线教育 |
| 制造业 | 供应链/生产/工艺、MES/ERP、质量体系、精益生产 |
| 消费/零售 | 品牌/营销/渠道、GMV/转化率、SKU、用户运营 |

## JD 解析输出格式

解析 JD 后，应以结构化方式总结关键发现，供简历优化时参考：

```
【JD 解析结果】

**岗位**：高级前端工程师 | 互联网/科技行业
**经验**：3-5 年 | **学历**：本科及以上

**硬技能关键词**（按重要性排序）：
1. React（精通）— 核心框架，必须突出深度使用经验
2. TypeScript（熟练）— 日常开发语言
3. 微前端架构（熟悉）— 架构能力加分项
4. 性能优化（有经验）— 需要量化成果
5. Next.js（了解）— 加分项，如有经验则突出

**软技能关键词**：
- 跨团队协作（核心要求）
- 技术方案评审（中级+要求）
- 自驱力强（隐性要求）

**行业术语**：
- SSR（服务端渲染）
- Web Vitals（核心网页指标）
- CI/CD（持续集成/部署）

**隐性要求**：
- "有从 0 到 1 经验优先" → 需要展示项目搭建经历
- "技术热情" → 展示技术博客或开源贡献
- "大厂优先" → 突出规范化和大型项目经验

**简历调整建议**：
- 工作经历中重点突出 React + TypeScript 的深度使用
- 补充性能优化的量化数据
- 如有微前端经验，在架构设计中详细展示
- 技能标签与 JD 关键词对齐
```

## 简历匹配度评估

解析 JD 后，应对照用户简历评估匹配度：

### 评估维度

| 维度 | 权重 | 评估方法 |
|------|------|---------|
| 硬技能匹配 | 40% | JD 要求的技能在简历中是否体现 |
| 经验匹配 | 25% | 工作年限和项目复杂度是否达标 |
| 行业匹配 | 15% | 是否有同行业/相近行业经验 |
| 软技能匹配 | 10% | 沟通/协作/领导力是否有体现 |
| 其他加分项 | 10% | 证书/开源/学历/奖项等 |

### 匹配度等级

| 等级 | 匹配度 | 建议 |
|------|--------|------|
| 高度匹配 | 80%+ | 重点优化表述和关键词对齐 |
| 中度匹配 | 60-80% | 突出匹配部分，弱化不匹配部分 |
| 低度匹配 | <60% | 诚实告知差距，建议调整求职方向 |

## 注意事项

1. **不要编造**：如果用户没有某项 JD 要求的技能，不要虚构经验
2. **诚实表达**：部分满足的技能用"了解/熟悉"等准确描述
3. **重点突出**：将最匹配的技能和经验放在最显眼的位置
4. **关键词对齐**：确保简历中使用 JD 中的原始关键词表述
5. **避免过度优化**：不要将简历改得面目全非，保持真实性
