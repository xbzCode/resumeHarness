# 迭代规划

## 总体节奏

| 阶段 | 周期 | 交付物 | 目标 |
|------|------|--------|------|
| P0 | 2 周 | Agent 核心可用版 | Resume Agent 核心跑通：RuntimeBundle + Agent Loop + 记忆 + Skill，CLI/简单HTML可验证 |
| P1 | 2 周 | Web 服务可用版 | FastAPI + SSE 对话 + 简历下载，单用户完整流程 |
| P2 | 2.5 周 | 多用户版 | 认证 + 多租户隔离 + SQLite 迁移 + 正式 React 前端 |
| P3 | 2 周 | IM 渠道版 | 飞书/微信接入 + 渠道消息路由 |
| P4 | 2 周 | 增强版 | MCP 工具 + PDF 高质量导出 + 领域 Skill |
| P5 | 持续 | 优化迭代 | 性能优化 + 体验打磨 + 新功能 |

## P0：Agent 核心可用版 (2 周)

**目标**：Resume Agent 核心能力跑通——精简版 RuntimeBundle 构建、Agent Loop、DeepSeek 对接、记忆注入、Skill 加载，通过 CLI 或最简 HTML 页面可验证完整对话流程。

> **设计原则**：P0 聚焦 agent 后端功能，不涉及认证和前端 UI 开发。Web 端仅提供一个极简 HTML 页面用于功能验证。开发模式使用默认 user_id `dev_user`。

### P0-1：项目骨架 + OpenHarness 裁剪 (3 天)

| 任务 | 说明 |
|------|------|
| 创建 `resume_agent/` 包结构 | 按架构文档建立目录和模块 |
| 实现 `build_resume_runtime()` | 精简版 RuntimeBundle 构建，跳过本地工具 |
| 接入 DeepSeek API | 配置 OpenAICompatibleClient，支持多 Key 轮询（`api_key_pool.py`） |
| 验证 Agent Loop | 单元测试：提交 prompt → 流式返回 → 工具调用 |

**验收标准**：`resume_agent` 包可 import，`build_resume_runtime()` 可创建能对话的 QueryEngine。

### P0-2：简历领域提示词 + Skill + 记忆 (4 天)

| 任务 | 说明 |
|------|------|
| 编写 `resume-skill.md` | 简历优化的领域知识：结构、关键词匹配、STAR 法则等 |
| 系统提示词模板 | 角色定义 + 输出格式约束（Markdown 简历格式） |
| 提示词组装逻辑 | 复用 `prompts/context.py`，注入 resume-skill + 用户记忆 |
| 用户记忆加载 | 按 user_id 加载记忆目录，注入系统提示词 |
| `memory_write` 工具 | LLM 主动调用写入记忆文件（职业偏好、技能标签、优化历史） |
| `skill_loader` 工具 | LLM 主动加载 skill 内容到上下文 |

**验收标准**：对话中要求生成简历，LLM 输出结构化的 Markdown 简历内容；LLM 可通过 `memory_write` 持久化用户偏好并在后续对话中生效。

### P0-3：SSE 对话端点 + 极简验证页面 (3 天)

| 任务 | 说明 |
|------|------|
| FastAPI 应用骨架 | 路由注册、中间件、CORS |
| `POST /api/chat` SSE 端点 | SSE 流式对话，StreamEvent → SSE event 推送 |
| `SessionPool` 实现 | 单用户单会话，消息历史内存存储 |
| StreamEvent → SSE 序列化 | 将 StreamEvent 序列化为 `data: {...}\n\n` 格式 |
| 极简 HTML 验证页面 | 单文件 HTML + fetch SSE，仅用于功能验证，非正式 UI |

**验收标准**：通过极简 HTML 页面或 curl 发送 prompt，可收到 SSE 流式回复。

## P1：Web 服务可用版 (2 周)

**目标**：FastAPI 完整 Web 服务跑通，SSE 流式对话 + 简历渲染下载，单用户完整流程。仍不涉及认证，开发模式下直接使用。

### P1-1：简历渲染与下载 (3 天)

| 任务 | 说明 |
|------|------|
| `resume_renderer.py` | Markdown → PDF (weasyprint)，实现渲染队列（同时仅 1 个渲染任务） |
| 简历快照持久化 | LLM 生成简历后自动保存到 `resumes/{resume_id}.md`，与对话会话解耦 |
| `GET /api/resume/{resume_id}/download` | 简历下载端点（使用 resume_id，非 session_id） |
| `GET /api/resume/{resume_id}/preview` | 简历预览端点 |
| `GET /api/resume/templates` | 获取可用简历模板列表 |
| 端到端测试 | 从对话到下载完整流程 |

**验收标准**：对话生成简历 → 调用下载端点 → 获取 PDF 文件；会话淘汰后简历仍可下载。

### P1-2：记忆管理 API + 用户配置 + web_fetch (4 天)

| 任务 | 说明 |
|------|------|
| 记忆 CRUD API | `GET/PUT/DELETE /api/memory/{doc_name}` |
| 简历上传 | `POST /api/memory/upload`，解析并存为 `简历原文.md` |
| 用户级 Settings | 每用户可覆盖全局配置（简历模板偏好、语言风格等） |
| 记忆注入提示词 | 对话时自动加载用户记忆文件 |
| `web_fetch` 工具 | 抓取 URL 网页内容，用于 JD 链接解析 |

**验收标准**：用户上传简历后，后续对话自动参考原始简历内容；提供 JD 链接后 Agent 自动抓取并分析。

### P1-3：工具与系统 API (3 天)

| 任务 | 说明 |
|------|------|
| `GET /api/tools` | 查询可用工具列表 |
| `GET /api/mcp/status` | MCP 服务状态 |
| `GET /api/skills` | Skill 列表 |
| `GET /api/sessions` | 列出历史会话 |
| `GET /api/sessions/{id}` | 加载历史会话 |

**验收标准**：各 API 端点正常响应，可在极简页面上查询工具和会话信息。

## P2：多用户版 (2.5 周)

**目标**：认证体系完整，10 用户并发，每用户独立数据，SQLite 数据存储，正式 React Web 前端上线。

### P2-1：用户认证 + SQLite 迁移 (4 天)

| 任务 | 说明 |
|------|------|
| JWT 认证 | 注册/登录/token 刷新 |
| 认证中间件 | SSE 和 REST 都需要鉴权 |
| SQLite 数据库 | 引入 SQLite，认证数据、会话元数据、简历索引迁移 |
| 用户数据存储 | `~/.resume_agent/users/{user_id}/` 目录结构 + SQLite 索引 |
| 开发模式默认 user_id 移除 | 切换为正式认证模式 |

**验收标准**：未认证请求被拒绝，JWT 有效期内可正常访问；认证数据存储在 SQLite 中。

### P2-2：多租户隔离 (3 天)

| 任务 | 说明 |
|------|------|
| 用户级 Memory 隔离 | 按 `user_id` 隔离记忆目录 |
| 会话隔离 | 每用户独立会话列表和消息历史 |
| SessionPool 多用户 | 按 `user_id + session_id` 管理会话 |
| SSE 认证适配 | SSE 请求通过 Authorization header 传递 JWT |
| MCP 认证动态注入 | `mcp_auth.py` 按用户动态注入 MCP 工具认证信息 |

**验收标准**：用户 A 看不到用户 B 的对话和记忆；不同用户调用邮件 MCP 使用各自的 auth token。

### P2-3：Web 前端正式版 (7 天)

| 任务 | 说明 |
|------|------|
| React 项目搭建 | 创建 React SPA 项目，配置路由和状态管理 |
| 登录/注册页面 | 账号密码登录 + JWT 管理 |
| 对话界面 | 流式对话 UI，支持 Markdown 渲染 |
| 简历预览 + 下载 | 简历内容预览、模板选择、PDF/Markdown 下载 |
| 记忆管理页面 | 记忆文件列表、查看、编辑、简历上传 |
| 多会话管理 | 会话列表、切换、删除 |
| 响应式适配 | 移动端基本可用 |

**验收标准**：Web 页面登录后可完整使用对话、简历生成、预览、下载功能。

## P3：IM 渠道版 (2 周)

**目标**：飞书/微信可收发消息，对话生成简历。

### P3-1：飞书渠道接入 (3 天)

| 任务 | 说明 |
|------|------|
| 复用 `FeishuAdapter` | 从 `channels/impl/feishu.py` 移植 |
| 飞书事件订阅 | 配置 Webhook URL + 验证 token |
| sender_id → user_id 映射 | 首次消息自动创建用户 |
| 消息长度处理 | 超长回复分段发送 |

**验收标准**：飞书发消息 → Agent 回复 → 简历内容以消息形式返回。

### P3-2：微信/企微渠道 (3 天)

| 任务 | 说明 |
|------|------|
| `WeChatAdapter` 实现 | 实现 `ChannelAdapter` 接口 |
| 企业微信 Webhook | 接收消息 + 发送回复 |
| 消息格式适配 | 微信消息格式（文本/Markdown 卡片） |

**验收标准**：企业微信发消息 → Agent 回复。

### P3-3：渠道统一路由 (1 天)

| 任务 | 说明 |
|------|------|
| GatewayBridge 集成 | 复用 ohmo 的 MessageBus + GatewayBridge + ChannelAdapter 基类 |
| 渠道消息统一分发 | Web / 飞书 / 微信消息统一进入 SessionPool |
| 渠道特定处理 | 各渠道的消息格式差异处理 |

**验收标准**：同一用户在飞书和 Web 端的会话数据共享。

## P4：增强版 (2 周)

**目标**：MCP 工具扩展 + PDF 高质量导出 + 领域 Skill 精调。

### P4-1：MCP 工具接入 (3 天)

| 任务 | 说明 |
|------|------|
| McpClientManager 共享单例 | 进程级创建，所有会话复用 |
| PDF 转换 MCP | 部署 PDF 转换 HTTP MCP 服务（替代主进程内 weasyprint，隔离渲染） |
| 邮件发送 MCP | 用户可通过对话让 Agent 发送简历到邮箱 |
| stdio-to-http 代理 | 为需要的 stdio MCP 工具部署代理 |
| 用户级 MCP 隔离 | 邮件 MCP 的 auth token 按用户隔离（复用 `mcp_auth.py`） |

**验收标准**：对话中"把简历发到我邮箱" → Agent 调用邮件 MCP 发送。

### P4-2：简历模板与高质量 PDF (3 天)

| 任务 | 说明 |
|------|------|
| 多套简历 CSS 模板 | professional / academic / creative |
| 模板选择 API | `GET /api/resume/templates` + 下载时指定模板 |
| 中文 PDF 渲染优化 | weasyprint 中文字体嵌入 |

**验收标准**：用户可选择不同模板下载 PDF，中文渲染无乱码。

### P4-3：领域 Skill 精调 (2 天)

| 任务 | 说明 |
|------|------|
| `resume-skill.md` 迭代 | 根据实际使用反馈优化提示词和流程 |
| 行业细分 Skill | `resume-tech.md`、`resume-finance.md` 等行业专项 |
| JD 解析 Skill | 招聘需求结构化提取 |

**验收标准**：不同行业 JD 的简历匹配度明显提升。

### P4-4：速率限制 + 监控 (2 天)

| 任务 | 说明 |
|------|------|
| API 速率限制 | 按 user_id 维护令牌桶 |
| DeepSeek 429 处理 | 多 Key 轮询 + 排队重试 + 用户提示 |
| 基础监控 | 请求量/延迟/错误率日志 |

**验收标准**：10 用户并发不触发 DeepSeek 速率限制，429 时优雅降级。

## P5：优化迭代 (持续)

### 性能优化

| 任务 | 优先级 | 说明 |
|------|--------|------|
| API Client 连接池调优 | 中 | httpx 连接池参数优化 |
| 会话 LRU 淘汰 | 低 | 超时淘汰空闲 QueryEngine 释放内存 |
| 响应缓存 | 低 | 相同 JD 的简历建议缓存 |
| Session Storage 迁移 Redis | 低 | 如需多实例部署再考虑 |

### 体验打磨

| 任务 | 优先级 | 说明 |
|------|--------|------|
| 多轮优化 | 高 | 支持对话中逐步修改简历 |
| 简历对比视图 | 中 | 原文 vs 优化版并排展示差异 |
| 简历评分 | 中 | 对生成简历与 JD 的匹配度评分 |
| 导出格式扩展 | 低 | DOCX 等更多格式 |

### 新功能

| 任务 | 优先级 | 说明 |
|------|--------|------|
| 招聘网站 MCP | 中 | 自动抓取 JD 描述 |
| 简历版本管理 | 低 | 保存历次优化版本 |
| 批量投递 | 低 | 一次生成多份不同岗位的简历 |
| 多语言简历 | 低 | 中英双语简历生成 |
