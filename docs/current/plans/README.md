# 需求开发规划

本目录管理当前迭代的需求规划文件。

## 目录结构

```
docs/current/plans/      # 当前迭代的需求规划
docs/plans/              # 历史归档
├── active/              # （已废弃，由 current/plans/ 替代）
└── done/                # （已废弃，随迭代归档到 archive/）
```

## 工作流

```
新需求进入
    ↓
1. 在 roadmap.md 待办中新增任务（分配编号 P4-NN）
    ↓
2. 在 docs/current/plans/ 创建需求规划文件
    ↓
3. 开发执行（按规划文件逐步推进）
    ↓
4. 开发完成
    ├── 更新 changelog.md
    ├── 更新 roadmap.md（标记已完成）
    ├── 更新 bugs.md（如有缺陷修复）
    └── 在规划文件中填写完成总结（状态改为 ✅）
```

## 规划文件命名规范

格式：`P4-XX-简述.md`

- `P4-XX`：迭代编号，与 roadmap.md 中的编号一致
- `简述`：2-4 个汉字概括需求核心

示例：`P4-20-亮暗主题切换.md`

## 规划文件模板

```markdown
# P4-XX: 需求标题

## 元信息
- 编号：P4-XX
- 优先级：高/中/低
- 类型：需求/缺陷/变更
- 来源：用户需求 / 迭代规划 / 缺陷
- 状态：🟡 规划 → 🔵 开发中 → ✅ 已完成
- 创建时间：YYYY-MM-DD
- 完成时间：

## 需求描述
一句话目标 + 背景说明

## 技术方案
方案设计、关键决策

## 实现清单
- [ ] 任务1
- [ ] 任务2

## 涉及文件
- `path/to/file` — 改动说明

## 验收标准
- [ ] 标准1

## 完成总结
（完成后填写，记录实际做了什么、偏离了什么）
```
