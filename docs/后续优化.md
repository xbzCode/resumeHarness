# 后续优化规划

## 总体目标

- **可扩展**：不要硬编码，支持通过配置文件、插件机制扩展 Skill、MCP、提示词、模板等系统功能
- **有规范**：所有可扩展点必须有明确的规范说明，第三方按规范即可接入
- **好看**：页面美观、简洁、有设计感，不要AI味（颜色、布局、动画）
- **完整**：功能完善，覆盖 Skill 展示、MCP 管理、关于我、项目展示、模板配置等

---

## 一、当前存在问题

### 1.1 前端问题

| 问题 | 说明 |
|------|------|
| 配色单一 | 所有 CSS 变量使用纯灰度 `oklch(* 0 0)`，无品牌色、无视觉层次 |
| 无主题切换 | `next-themes` 已安装但未使用，无亮/暗模式 |
| 无过渡动画 | 路由切换、消息出现、面板展开均无动画 |
| 布局不合理 | Chat 页简历预览挤压消息；Resumes 页卡片缺标题/缩略图；Memory 页列表/详情用 Tab 切换 |
| 功能页面缺失 | 无 Skill 展示页、关于我页、项目展示页、模板配置页 |
| 用户设置不完善 | 后端支持 `default_template`/`language_style`/`output_language` 但前端未暴露 |

### 1.2 后端问题

| 问题 | 说明 |
|------|------|
| 供应商锁定 | `DEEPSEEK_API_KEY`/`base_url`/`model` 硬编码，切换 LLM 需改代码 |
| 系统 Prompt 硬编码 | ~150 行大字符串写在 Python 源码中，无版本管理、无法配置 |
| SQLite 同步驱动 | `db.py` 用同步 `sqlite3`，在 async FastAPI 中可能阻塞事件循环 |
| CORS 全开 | `allow_origins=["*"]`，生产环境不安全 |
| 文件 I/O 无并发保护 | 记忆文件写入无锁，`web_fetch` 缓存无大小限制 |

### 1.3 可扩展性差距

| 子系统 | 当前状态 | 核心问题 |
|--------|---------|---------|
| Skill | 4 个 `.md` 文件，`SkillLoaderTool` 仅允许加载 `resume-skill` | LLM 无法动态加载其他技能；分类映射硬编码 |
| MCP | 仅 HTTP 类型，3 个默认服务器固定 localhost | 无运行时增删；`is_read_only` 靠名称魔法推断；无共享框架层 |
| Prompt | Python 源码硬编码 | 无模板文件、无版本管理、无用户自定义注入点 |
| 模板 | 3 套模板硬编码在包内 | 无元数据/注册表/缩略图；前端组件映射写死 |
| 工具 | 3 个内置工具 + MCP 代理 | 无插件发现机制；无分类/权限声明 |

## 二、扩展规范设计

> **核心原则**：每个可扩展点必须定义 **格式规范 + 元数据规范 + 验证规则 + 集成指南**，第三方按规范即可接入，无需改代码。

### 2.1 Skill 规范

#### 2.1.1 格式规范

Skill 文件为 **Markdown + YAML Front Matter** 格式：

```markdown
---
name: resume-tech
version: "1.0.0"
category: 行业技能
tags: [互联网, 科技, 前端, 后端, AI]
industry: [tech, internet]
depends: [resume-skill]
token_budget: 4000
author: ResumeAgent
description: 互联网/科技行业专项技能，包含前后端/AI/产品运营关键词分类和量化策略
---

## 行业概述
（技能正文内容...）
```

#### 2.1.2 Front Matter 元数据规范

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | string | 是 | 技能唯一标识符，与文件名 stem 一致 |
| `version` | string | 是 | 语义化版本号（SemVer） |
| `category` | string | 是 | 分类标签，用于 UI 展示分组 |
| `tags` | string[] | 否 | 关键词标签，用于搜索和推荐 |
| `industry` | string[] | 否 | 适用行业标识符列表，用于自动加载映射 |
| `depends` | string[] | 否 | 依赖的其他技能名称列表 |
| `token_budget` | int | 否 | 预估 Token 占用，用于预算控制 |
| `author` | string | 否 | 作者/来源 |
| `description` | string | 是 | 技能描述（一句话，用于列表展示） |

#### 2.1.3 验证规则

- Front Matter 必须存在且包含 `name`、`version`、`category`、`description`
- `name` 必须与文件名 stem 一致
- `name` 格式：`^[a-z][a-z0-9-]*$`（小写字母开头，允许小写字母/数字/连字符）
- `depends` 中引用的技能必须存在
- 文件大小不超过 64KB
- 正文必须包含至少一个 `##` 级标题

#### 2.1.4 加载机制变更

- `SkillLoaderTool` 支持加载**所有**已注册技能（不再限制为 `resume-skill`）
- 行业→技能映射从 `_SKILL_CATEGORIES` 硬编码改为读取 Front Matter 的 `industry` 字段自动构建
- `extra_skill_dirs` 参数实际生效，支持外部技能目录

### 2.2 MCP 服务器规范

#### 2.2.1 协议规范

MCP 服务器必须实现以下 HTTP 端点：

| 端点 | 方法 | 请求体 | 响应 | 说明 |
|------|------|--------|------|------|
| `/health` | GET | — | `{"status": "ok", "version": "1.0.0"}` | 健康检查 |
| `/tools/list` | POST | — | `{"tools": [ToolSpec]}` | 工具发现 |
| `/tools/call` | POST | `{"name": "...", "arguments": {...}}` | `McpCallResult` | 工具调用 |

#### 2.2.2 ToolSpec 规范

```json
{
  "name": "scrape_jd",
  "description": "抓取招聘网站职位描述",
  "inputSchema": {
    "type": "object",
    "properties": {
      "url": {"type": "string", "description": "招聘网站 URL"},
      "max_length": {"type": "integer", "default": 4000}
    },
    "required": ["url"]
  },
  "annotations": {
    "readOnlyHint": true,
    "destructiveHint": false,
    "idempotentHint": true,
    "category": "网络抓取",
    "timeout_ms": 30000
  }
}
```

#### 2.2.3 Annotations 元数据规范

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `readOnlyHint` | bool | 是 | 是否只读（不产生副作用） |
| `destructiveHint` | bool | 是 | 是否有破坏性（如删除数据） |
| `idempotentHint` | bool | 否 | 是否幂等 |
| `category` | string | 否 | 工具分类标签 |
| `timeout_ms` | int | 否 | 建议超时时间（毫秒） |

> **关键变更**：`is_read_only()` 不再通过名称魔法推断，改为读取 `annotations.readOnlyHint`。未声明时默认 `false`（安全降级）。

#### 2.2.4 McpCallResult 规范

```json
{
  "content": [{"type": "text", "text": "结果文本"}],
  "isError": false,
  "errorMessage": null
}
```

#### 2.2.5 MCP 服务器注册配置规范

```json
{
  "mcp_servers": {
    "server_name": {
      "type": "http",
      "url": "http://localhost:9102",
      "headers": {},
      "enabled": true,
      "description": "JD 抓取服务",
      "auto_reconnect": true,
      "health_check_interval": 60
    }
  }
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `type` | string | 是 | 传输协议，当前仅 `"http"` |
| `url` | string | 是 | 服务器地址 |
| `headers` | object | 否 | 全局请求头 |
| `enabled` | bool | 否 | 是否启用，默认 `true` |
| `description` | string | 否 | 服务器描述 |
| `auto_reconnect` | bool | 否 | 是否自动重连，默认 `true` |
| `health_check_interval` | int | 否 | 健康检查间隔（秒），0=不检查 |

#### 2.2.6 共享 MCP 框架

提供 Python 基类 `McpServerBase`，第三方只需实现工具逻辑：

```python
class McpServerBase:
    """MCP 服务器基类，自动实现协议端点。"""

    server_name: str = ""
    server_version: str = "1.0.0"

    def register_tool(self, name, description, input_schema, handler, annotations=None): ...
    def run(self, host="0.0.0.0", port=9100): ...
```

### 2.3 简历模板规范

#### 2.3.1 文件结构

每个模板由以下文件组成：

```
templates/{template_name}/
├── template.json      # 模板元数据（必填）
├── template.html      # Jinja2 HTML 模板（必填）
├── preview.png        # 预览缩略图（推荐）
└── README.md          # 模板说明（推荐）
```

#### 2.3.2 template.json 元数据规范

```json
{
  "name": "professional",
  "version": "1.0.0",
  "display_name": "简洁商务",
  "description": "双栏侧边栏布局，适用于互联网/科技行业",
  "author": "ResumeAgent",
  "layout": "two-column",
  "color_scheme": {
    "primary": "#1e293b",
    "accent": "#3b82f6",
    "background": "#ffffff"
  },
  "recommended_industries": ["tech", "internet", "engineering"],
  "required_fields": ["name", "experience"],
  "optional_fields": ["projects", "summary"],
  "supports_dark_mode": false,
  "page_size": "A4",
  "preview": "preview.png"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | string | 是 | 模板唯一标识符，与目录名一致 |
| `version` | string | 是 | 语义化版本号 |
| `display_name` | string | 是 | UI 展示名称 |
| `description` | string | 是 | 模板风格描述 |
| `author` | string | 否 | 作者 |
| `layout` | string | 否 | 布局类型：`single-column`/`two-column`/`card` |
| `color_scheme` | object | 否 | 主色方案，用于前端预览组件匹配 |
| `recommended_industries` | string[] | 否 | 推荐行业，用于智能模板推荐 |
| `required_fields` | string[] | 否 | 模板必须的 ResumeData 字段 |
| `optional_fields` | string[] | 否 | 模板可选的 ResumeData 字段 |
| `supports_dark_mode` | bool | 否 | 是否支持暗色主题 |
| `page_size` | string | 否 | 页面尺寸，默认 `A4` |
| `preview` | string | 否 | 预览图文件名 |

#### 2.3.3 Jinja2 模板变量

模板接收统一的 `context` 变量：

```python
{
    "resume": ResumeData,           # 简历结构化数据（见 ResumeData 模型）
    "contact_text": str,            # 格式化联系方式文本
    "has_experience": bool,         # 是否有工作经历
    "has_education": bool,          # 是否有教育背景
    "has_skills": bool,             # 是否有技能
    "has_projects": bool,           # 是否有项目经历
    "has_summary": bool,            # 是否有个人简介
    "template_config": dict,        # 用户自定义模板参数（预留）
}
```

#### 2.3.4 模板 CSS 规范

```css
/* 必须包含 */
@page { size: A4; margin: 2cm; }
@media print { /* 避免分页断裂 */ }

/* 中文字体栈 */
body { font-family: "SimHei", "Microsoft YaHei", "PingFang SC", "Noto Sans SC", sans-serif; }

/* 容错渲染 */
/* 所有 ResumeData 字段必须用 {% if %} 判断空值后再渲染 */
```

#### 2.3.5 验证规则

- `template.json` 必须存在且可解析为合法 JSON
- `name` 与目录名一致
- HTML 模板必须包含 `{{ resume.name }}` 变量引用
- HTML 模板必须包含 `@page` CSS 规则
- `required_fields` 中的字段必须在 HTML 中有对应渲染逻辑
- 提供模板校验 CLI：`python -m resume_agent.tools.validate_template <template_dir>`

### 2.4 工具规范

#### 2.4.1 内置工具规范

继承 `BaseTool` 并实现以下接口：

```python
class BaseTool(ABC):
    name: str                    # 唯一标识符，格式: ^[a-z][a-z0-9_]*$
    description: str             # LLM 可读描述，不超过 200 字
    input_model: type[BaseModel] # Pydantic 输入模型
    category: str = "其他"       # 工具分类标签
    is_read_only_default: bool = False  # 默认只读标记

    @abstractmethod
    async def execute(self, arguments, context) -> ToolResult: ...

    def is_read_only(self, arguments) -> bool:
        return self.is_read_only_default
```

#### 2.4.2 工具元数据扩展

| 字段 | 类型 | 说明 |
|------|------|------|
| `category` | string | 分类标签：`网络`/`文件`/`记忆`/`技能`/`MCP代理`/`其他` |
| `is_read_only_default` | bool | 默认只读标记（替代名称魔法推断） |
| `timeout_ms` | int | 建议超时时间 |
| `requires_auth` | bool | 是否需要用户级认证 |

#### 2.4.3 工具发现机制

支持两种工具注册方式：

1. **代码注册**（内置工具）：在 `_get_shared_tool_registry()` 中 `register()`
2. **目录扫描**（插件工具）：扫描 `tools/plugins/` 目录下的 Python 模块，自动导入并注册 `BaseTool` 子类

```python
# tools/plugins/my_tool.py
from resume_agent.tools.base import BaseTool, ToolResult

class MyCustomTool(BaseTool):
    name = "my_custom_tool"
    description = "自定义工具示例"
    category = "自定义"
    ...
```

### 2.5 提示词规范

#### 2.5.1 文件结构

```
prompts/
├── system_prompt.md          # 系统提示词主模板
├── segments/                  # 分段模板
│   ├── role.md               # 角色定义
│   ├── output_format.md      # 输出格式约束
│   ├── jd_analysis.md        # JD 分析要求
│   ├── work_principles.md    # 工作原则
│   ├── multi_turn_rules.md   # 多轮优化规则
│   └── tool_usage.md         # 工具使用规范（自动从 ToolRegistry 生成）
└── custom/                    # 用户自定义指令
    └── {user_id}/            # 按用户隔离
        └── instructions.md   # 用户自定义指令
```

#### 2.5.2 模板变量

提示词模板支持以下变量注入：

| 变量 | 来源 | 说明 |
|------|------|------|
| `{{memory_text}}` | 用户记忆文件 | 自动加载的用户记忆内容 |
| `{{skill_text}}` | 技能文件 | 自动加载的技能内容 |
| `{{tool_descriptions}}` | ToolRegistry | 所有可用工具的描述（自动生成） |
| `{{user_instructions}}` | 用户自定义 | 用户注入的自定义指令 |
| `{{template_list}}` | 模板注册表 | 可用模板列表 |
| `{{current_date}}` | 系统 | 当前日期 |

#### 2.5.3 用户自定义指令

用户可在设置页或 `custom/{user_id}/instructions.md` 中添加自定义指令，该指令会注入到系统提示词的"用户自定义规则"段中：

```markdown
<!-- custom/{user_id}/instructions.md -->
- 简历中不要使用第一人称
- 工作经历按时间倒序排列
- 技能标签不超过 8 个
```

#### 2.5.4 Token 预算管理

| 段落 | 预算（Token） | 说明 |
|------|-------------|------|
| 角色定义 | 500 | 固定 |
| 输出格式 | 300 | 固定 |
| 工具描述 | 500 | 动态生成 |
| 用户记忆 | 2000 | 按 `max_bytes` 换算 |
| 通用技能 | 3000 | `resume-skill.md` |
| 行业技能 | 2000 | 动态加载 |
| JD 技能 | 1500 | 按需加载 |
| 用户自定义 | 500 | 用户指令 |
| **合计上限** | **~10000** | 超出时按优先级截断 |

### 2.6 记忆文件规范

#### 2.6.1 文件格式

```markdown
---
name: 职业偏好
writable: true
max_size_kb: 4
auto_created: true
description: 用户表达的求职偏好和写作风格
---

（用户偏好内容...）
```

#### 2.6.2 Front Matter 元数据

| 字段 | 类型 | 说明 |
|------|------|------|
| `name` | string | 记忆文件显示名称 |
| `writable` | bool | 是否允许 LLM 通过 `memory_write` 写入 |
| `max_size_kb` | int | 文件大小上限（KB） |
| `auto_created` | bool | 是否首次使用时自动创建 |
| `description` | string | 文件用途描述 |

#### 2.6.3 变更

- `WRITABLE_MEMORY_FILES` 从硬编码白名单改为读取 Front Matter 的 `writable` 字段
- `简历原文.md` 的 `writable: false`，其他文件 `writable: true`
- 用户可创建自定义记忆文件，自动获得 `writable: true`
